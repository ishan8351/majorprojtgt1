# Healthcare Statutory Compliance & Governance Matrix

This specification documents technical control mapping for the Healthcare AI & Genomic Telemedicine Data Lake across **HIPAA**, **HITRUST CSF v11**, and **GDPR Article 9**.

---

## 1. HIPAA Security Rule (45 CFR §164.308 / §164.312) Audit Crosswalk

| Section | Title & Requirement | Cloud Resource | Current State | RegRadar Remediation Mechanism |
| :--- | :--- | :--- | :--- | :--- |
| **§164.312(a)(2)(iv)** | **Encryption and Decryption (Addressable):** Encrypt ePHI at rest using strong cryptographic standards. | `aws_s3_bucket.raw_genomics_lake` | Unencrypted (`CKV_AWS_19`) | **Additive Attachment:** Synthesizes `aws_s3_bucket_server_side_encryption_configuration` without altering base bucket. |
| **§164.308(a)(7)(ii)(A)** | **Data Backup Plan (Required):** Create and maintain retrievable exact copies of ePHI. | `aws_s3_bucket.clinical_research_lake` | Missing versioning (`CKV_AWS_21`) | **Additive Attachment:** Synthesizes `aws_s3_bucket_versioning` attachment enabling immutable object history. |
| **§164.312(b)** | **Audit Controls (Required):** Record and examine activity in systems containing ePHI. | `aws_cloudtrail.hipaa_cloudtrail` | Unencrypted log files (`CKV_AWS_36`) | **In-Place Attribute:** Attaches `kms_key_id` referencing customer-managed key. |
| **§164.312(e)(1)** | **Transmission Security (Addressable):** Guard against unauthorized network access to ePHI. | `aws_security_group.telehealth_alb_sg` | Ingress allows port 22 from `0.0.0.0/0` (`CKV_AWS_24`) | **Pre-Flight Invariant Gating:** Evaluates diff and eliminates public port 22 exposure. |
| **§164.312(a)(1)** | **Access Control (Required):** Least privilege access limiting system mutations. | `aws_iam_policy.genomic_processor_policy` | Unconstrained wildcard write (`CKV_AWS_40`) | **Human Escalation Review:** Flags wildcard actions for operator scoping. |

## 3. GDPR Article 9 (Special Categories: Genetic & Health Data)

| Clause | Regulatory Mandate | IaC Implementation | Security Guarantee |
| :--- | :--- | :--- | :--- |
| **Article 9(1)** | Prohibition of unconstrained genetic data processing without explicit technical safeguards. | Dedicated `aws_kms_key.genomic_kms_key` encrypting all DNA sequences in `raw_genomics_lake`. | Cryptographic separation between health metrics and genetic profiles. |
| **Article 32(1)(a)** | Pseudonymisation and encryption of personal data by design and default. | Automated additive encryption attachments generated by RegRadar Synthesizer Agent. | Guarantees compliance without disrupting active clinical data pipelines. |
